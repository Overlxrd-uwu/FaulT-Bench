==================================================
Scenario: kath4-router11-default-route-missing
Topology: Kath4
Fault family: missing static / default
==================================================

[PROMPT-TO-AGENT]
router11 (one of the OSPF spokes) shows no routing path to
external networks. Operators report router11 has OSPF Full
adjacencies but cannot ping the Campus 2 server-side SVI
(10.5.0.254). Other spokes (router10, router8) reach it fine.
Find the difference on router11.

[INJECTION]
device: router11
action: remove default route
cmd: ip route del default 2>/dev/null; vtysh -c "configure terminal" -c "router ospf" -c "no default-information originate" -c "exit" -c "exit" 2>/dev/null

[POST-INJECT-CHECK]
router11  ip route show default          => expect empty

[GROUND-TRUTH]
Affected component: router11 default route
Mechanism: router11 originally had a default route (either
  static or learned via OSPF default-information). When
  removed, any destination not explicitly in router11's RIB
  has no next hop. OSPF adjacencies stay up because they
  use directly-connected links, but transit to 10.5.0.254
  (which is reachable only via the default + intermediate
  hops) fails.
Localization: router11
Root cause: default route removed on router11
Fix: `ip route add default via <next-hop>` or re-enable
  default-information learning

[FIX]
`ip route add default via <next-hop>` or re-enable
  default-information learning

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm that router11 has Full OSPF adjacencies
   (so the data plane failure is not a neighbor problem) but cannot
   reach 10.5.0.254 while other spokes (router10, router8) can.
2. Inspect the routing table on router11: run `ip route show` — the
   default route entry is absent, immediately explaining why any
   destination not in the directly-connected or OSPF-learned specific
   routes has no next hop.
3. Check whether a default route should exist: compare against router10
   or router8 to confirm that a default route (static or OSPF
   default-information) is the expected differentiator.
4. Confirm OSPF adjacencies are intact: run `show ip ospf neighbor` on
   router11 to verify Full state, ruling out a neighbor failure as the
   cause of the connectivity loss.
5. Localize to the lowest-layer root cause: the default route is missing
   from router11's RIB, ruling out a link failure, an OSPF neighbor
   problem, or a misconfigured specific prefix.
