Scenario: kath4-switch4-trunk-vlan5-down
Topology: Kath4
Fault family: VLAN trunk subinterface down
==================================================

[PROMPT-TO-AGENT]
PC1, PC2, dc_pc5 (Campus 2 VLAN 5) report they cannot reach
their gateway 10.5.0.254 or anything beyond. Same Campus's
VLAN 6 PCs (PC3, PC4) are fine. switch4 link status looks UP,
sshswitch is healthy. Where's the break?

[INJECTION]
device: switch4
action: shut down the VLAN 5 trunk subinterface (eth0.5)
cmd: ip link set eth0.5 down

[POST-INJECT-CHECK]
switch4  ip -br link show eth0.5 | grep -c UP   => expect 0
pc1      ping -W2 -c2 10.5.0.254                => expect loss>0
pc3      ping -W2 -c2 10.6.0.254                => expect 0% loss

[GROUND-TRUTH]
Affected component: switch4 eth0.5 (VLAN 5 trunk subinterface
  to sshswitch)
Mechanism: switch4 carries VLAN 5 and VLAN 6 to sshswitch
  via the eth0 trunk. The VLAN 5 sub-interface eth0.5 was
  brought down — VLAN 5 access PCs are now isolated from
  sshswitch's br_v5 SVI. VLAN 6 (eth0.6) is unaffected.
Localization: switch4 eth0.5
Root cause: VLAN 5 trunk subinterface down on switch4
Fix: `ip link set eth0.5 up` on switch4

[FIX]
`ip link set eth0.5 up` on switch4

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm VLAN 5 PCs (PC1, PC2, dc_pc5) cannot
   reach their gateway or anything beyond, while VLAN 6 PCs (PC3, PC4)
   are unaffected and sshswitch is reported healthy — isolating the
   fault to the VLAN 5 path between switch4 and sshswitch.
2. Check the host-side L3 config: verify PC1's gateway is 10.5.0.254
   (sshswitch br_v5 SVI) and the IP config is correct, pointing to a
   switch-path problem rather than a host issue.
3. Check the SVI state on sshswitch: verify br_v5 is UP and holds
   10.5.0.254 — confirming the gateway itself is fine and the break
   is in the access/trunk path.
4. Check the trunk subinterface on switch4: run `ip -br link show eth0.5`
   — eth0.5 (VLAN 5 subinterface) is DOWN while eth0.6 (VLAN 6) is UP,
   pinpointing the fault.
5. Localize to the lowest-layer root cause: VLAN 5 trunk subinterface
   eth0.5 on switch4 is down, ruling out an sshswitch SVI failure or
   a PC misconfiguration.
