==================================================
Scenario: kath4-sshswitch-vlan6-wrong-ip
Topology: Kath4
Fault family: SVI IP misconfig (wrong gateway address)
==================================================

[PROMPT-TO-AGENT]
PC3 and PC4 in Campus 2 VLAN 6 report their gateway (10.6.0.254)
no longer responds. Other Campus 2 PCs (PC1, PC2, dc_pc5 on
VLAN 5) are fine. Identify the misconfiguration.

[INJECTION]
device: sshswitch
action: change br_v6 SVI IP from .254 to .200
cmd: |
  ip addr del 10.6.0.254/24 dev br_v6
  ip addr add 10.6.0.200/24 dev br_v6

[POST-INJECT-CHECK]
sshswitch  ip -4 addr show br_v6 | grep -c "10.6.0.254"  => expect 0
sshswitch  ip -4 addr show br_v6 | grep -c "10.6.0.200"  => expect 1
pc3        ping -W2 -c2 10.6.0.254                    => expect loss>0
pc3        ping -W2 -c2 10.6.0.200                    => expect 0% loss

[GROUND-TRUTH]
Affected component: sshswitch br_v6 SVI IP address
Mechanism: PCs have their default route hard-coded to
  10.6.0.254 (the standard Cisco SVI VRRP-style address).
  sshswitch's br_v6 was reconfigured to 10.6.0.200, so
  ARP for 10.6.0.254 gets no reply — packets can't egress
  the subnet. The new address .200 IS reachable, but no host
  knows to use it.
Localization: sshswitch
Root cause: br_v6 SVI IP set to 10.6.0.200 instead of 10.6.0.254
Fix: re-set the IP — `ip addr del 10.6.0.200/24 dev br_v6 &&
  ip addr add 10.6.0.254/24 dev br_v6`

[FIX]
re-set the IP — `ip addr del 10.6.0.200/24 dev br_v6 &&
  ip addr add 10.6.0.254/24 dev br_v6`

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm that VLAN 6 PCs (PC3, PC4) cannot reach
   their gateway 10.6.0.254 or any off-subnet destination, while VLAN 5
   PCs are unaffected — isolating the fault to the VLAN 6 gateway path.
2. Check the host-side L3 config: verify PC3's default gateway is still
   set to 10.6.0.254 (unchanged), establishing that the problem is on
   the switch side, not the host.
3. Check the SVI IP on sshswitch: run `ip -4 addr show br_v6` — the
   address is 10.6.0.200/24, not 10.6.0.254/24, revealing the
   misconfiguration.
4. Confirm the ARP consequence: note that 10.6.0.254 gets no ARP reply
   (no interface holds that address), while 10.6.0.200 is reachable —
   proving hosts are configured correctly and only the switch IP is wrong.
5. Localize to the lowest-layer root cause: br_v6 SVI IP on sshswitch
   is set to 10.6.0.200 instead of 10.6.0.254, ruling out a VLAN trunk
   failure or host misconfiguration.
