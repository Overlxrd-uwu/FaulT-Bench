==================================================
Scenario: kath4-router7-r10-link-down
Topology: Kath4
Fault family: WAN link cut (backbone)
==================================================

[PROMPT-TO-AGENT]
Some Campus 1 users report higher latency to Campus 2 services
but no full outage. router7 logs show an OSPF neighbor went
down. Network monitoring shows routing convergence finished
and traffic now takes an alternate path. Identify the failed link.

[INJECTION]
device: router7
action: shut down the link to router10
cmd: ip link set eth3 down

[POST-INJECT-CHECK]
router7  ip -br link show eth3 | grep -c UP                  => expect 0
pc5      ping -W2 -c2 10.5.0.1                               => expect 0% loss

[GROUND-TRUTH]
Affected component: router7 eth3 / router7<->router10 link (10.0.0.0/24)
Mechanism: router7 has multiple OSPF neighbors providing
  ECMP / backup paths into the backbone. With router7<->router10
  down, OSPF reconverges via the remaining router7<->router8
  and router7<->router16 paths. Traffic to Campus 2 takes
  slightly longer (extra hop) but no outage.
Localization: router7 eth3
Root cause: backbone link router7<->router10 (10.0.0.0/24) is down
Fix: `ip link set eth3 up` on router7

[FIX]
`ip link set eth3 up` on router7

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm there is no full outage — traffic to
   Campus 2 still succeeds via an alternate path — but some users see
   higher latency, and router7 logged an OSPF neighbor going down.
2. Check interface/link state on router7: identify which physical
   interface is down; `ip -br link show` reveals eth3 is DOWN.
3. Confirm the lost OSPF adjacency: run `show ip ospf neighbor` on
   router7 to verify the router10 adjacency is gone, establishing
   that the link failure caused the neighbor drop, not a protocol change.
4. Correlate route convergence: confirm OSPF reconverged via the
   remaining paths (router7<->router8 and router7<->router16); traffic
   taking an extra hop explains the latency increase without an outage.
5. Localize to the lowest-layer root cause: physical link router7
   eth3 (router7<->router10, 10.0.0.0/24) is down, not an OSPF
   misconfiguration or cost change on either router.
