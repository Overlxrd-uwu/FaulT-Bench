[PROMPT-TO-AGENT]
All Campus 2 PCs (PC1-4, dc_pc5) report they cannot reach
Campus 1 or the WAN. They CAN still ping their own gateways
(10.5.0.254, 10.6.0.254) on sshswitch. Find what cut Campus 2's
uplink.

[INJECTION]
device: sshswitch
action: bring down the bond toward router17 (eth6+eth7)
cmd: ip link set bond0 down

[POST-INJECT-CHECK]
sshswitch  ip link show bond0 | grep -c "state DOWN"  => expect >=1
pc1        ping -W2 -c2 172.16.10.5                                    => expect loss>0
pc1        ping -W2 -c2 10.5.0.254                                     => expect 0% loss (local SVI)

[GROUND-TRUTH]
Affected component: sshswitch bond0 (LACP to router17)
Mechanism: bond0 is sshswitch's only L3 uplink toward router17,
  carrying tagged VLAN 100 (servers — excluded from hosts),
  VLAN 200, and untagged VLAN 1 traffic toward the OSPF
  backbone. With bond0 down, sshswitch loses OSPF adjacency
  with router17 and Campus 2 becomes an island. Local gateways
  still respond because they're SVIs on sshswitch itself.
Localization: sshswitch
Root cause: bond0 (port-channel toward router17) is down on sshswitch
Fix: `ip link set bond0 up` on sshswitch

[FIX]
`ip link set bond0 up` on sshswitch

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm local gateways (10.5.0.254, 10.6.0.254)
   still respond — so sshswitch is alive and the fault is in the uplink
   path — but all off-campus destinations are unreachable for all
   Campus 2 PCs.
2. Check the bond/LACP state on sshswitch: run `cat /proc/net/bonding/bond0`
   or `ip -br link show bond0` — bond0 MII Status is down, confirming
   the port-channel is not forwarding.
3. Check the OSPF adjacency consequence: run `show ip ospf neighbor` on
   sshswitch — the adjacency to router17 is gone, because OSPF runs over
   bond0 and has lost its L3 path.
4. Confirm the uplink role: establish that bond0 (eth6+eth7) is
   sshswitch's only L3 path toward router17 and the backbone — losing
   it makes Campus 2 an island while local SVIs remain reachable.
5. Localize to the lowest-layer root cause: bond0 is down on sshswitch,
   ruling out a router17-side failure, an OSPF misconfiguration, or a
   per-member-link failure that the bond would survive.
