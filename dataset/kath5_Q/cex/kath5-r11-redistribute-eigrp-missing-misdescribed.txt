[GROUND-TRUTH]
The root cause is IDENTICAL to kath5-r11-redistribute-eigrp-missing: R11's
`router ospf` block is missing `redistribute eigrp`. R11 is the only bridge between
the EIGRP cloud (R11/R12/R13 in AS 100) and the OSPF backbone (areas 0/1/2/3).
Without `redistribute eigrp`, the 102.x/112.x/113.x/120.x prefixes never become
OSPF LSAs, so pc12's 120.0.0.0/8 network is invisible to R1 and the rest of the
OSPF domain -- exactly the reported pattern.

The TWIST: the ticket asserts the wrong CAUSE -- a downed EIGRP<->OSPF boundary
link. The link is actually UP and forwarding: R11's interfaces are operationally up,
its EIGRP neighbors (R12/R13) are still Full, and R11 itself can reach the OSPF
backbone over that very link. Nothing physical failed. The "EIGRP cloud cut off
from the backbone" symptom is real, but the narrated cause (a maintenance-window
link failure) is a red herring -- a route-redistribution statement was removed, the
wire was not unplugged.

Design note (baseline, not a fault): the EIGRP side reaches the OSPF side via
STATIC DEFAULT routes on R12/R13 toward R11 -- intended design, since FRR's
eigrpd cannot redistribute OSPF into EIGRP (documented in r12.startup,
r13.startup, r11 frr.conf). So pc12's OUTBOUND packets still leave through R11
even after the injection; what breaks is the RETURN path -- the backbone loses
every route to 120.x/112.x/103.x the moment `redistribute eigrp` is removed.
An agent describing the missing return routes has found the injected fault;
the static-default arrangement itself is baseline design and must not be
reported as the anomaly.

Correct diagnosis: is_anomaly=true, faulty_devices = r11 (missing `redistribute
eigrp`). The agent must check Layer 1/2 (R11's boundary interfaces and EIGRP
adjacencies are up), then the redistribution config (`redistribute eigrp` absent
from R11's OSPF), and explicitly reject the "link down" narrative. A decisive tell:
R11 can reach the backbone itself (its default/redistribution the other way still
works) yet the EIGRP prefixes are missing from R1's RIB -- a live link with broken
one-way redistribution, not a dead wire. An agent that "confirms the down boundary
link" has followed the ticket's framing instead of the evidence. Fix: re-add
`redistribute eigrp` to R11's OSPF block.

[FIX]
