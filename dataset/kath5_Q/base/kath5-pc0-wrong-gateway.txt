==================================================
Scenario: kath5-pc0-wrong-gateway
Topology: Kath5
Fault family: host misconfig (wrong default gateway)
==================================================

[PROMPT-TO-AGENT]
pc0 (20.1.1.10) reports it cannot reach anything beyond its local subnet -- not
pc12 (120.1.1.x), not the OSPF backbone (10.x). Its local router interface is
still pingable. Nothing else in the network reports problems. Diagnose pc0.

[INJECTION]
device: pc0
action: point pc0's default route at a non-existent in-subnet gateway
cmd: |
  ip route del default 2>/dev/null
  ip route add default via 20.1.1.99

[POST-INJECT-CHECK]
pc0  ip route show default | grep -c "20.1.1.99"   => expect 1
pc0  ping -W2 -c2 120.1.1.10                        => expect loss>0

[GROUND-TRUTH]
Affected component: pc0 default-gateway configuration
Mechanism: pc0's correct gateway is 20.1.1.1 (its first-hop router). It was
  reconfigured to 20.1.1.99 -- an in-subnet but unassigned address -- so ARP for
  the gateway never resolves and pc0 cannot send any off-subnet traffic. The rest
  of the network (OSPF/EIGRP routing, pc12) is healthy; the fault is purely on
  pc0.
Localization: pc0
Root cause: pc0's default gateway set to 20.1.1.99 instead of 20.1.1.1
Fix: restore pc0's default route -- `ip route add default via 20.1.1.1`

[FIX]
restore pc0's default route -- `ip route add default via 20.1.1.1`

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm pc0 cannot reach any off-subnet destination
   (pc12, the OSPF backbone) while the rest of the network is healthy -- isolate
   to pc0's own configuration.
2. Inspect pc0's routing: `ip route show default` -- the default points at
   20.1.1.99 rather than the expected 20.1.1.1.
3. Confirm the ARP consequence: 20.1.1.99 is in-subnet but unassigned, so the
   gateway never resolves and no off-subnet packet egresses.
4. Localize to pc0's host config: rule out an OSPF/EIGRP routing fault (the rest
   of the network is converged and reachable from the routers) and a link failure
   (pc0's interface is up).
