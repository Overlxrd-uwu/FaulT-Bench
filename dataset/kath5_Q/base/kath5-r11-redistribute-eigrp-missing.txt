==================================================
Scenario: kath5-r11-redistribute-eigrp-missing
Topology: Kath5
Fault family: route redistribution missing
==================================================

[PROMPT-TO-AGENT]
A user on pc12 (R12's LAN, 120.1.1.x) reports they can reach
their direct neighbors (R12, R11) but cannot reach anything in
the OSPF backbone — no router1 (10.x), no router2 (1.x), no
remote LANs. From R11 itself, the OSPF backbone IS reachable.
Diagnose the gap.

[INJECTION]
device: r11
action: remove `redistribute eigrp` from r11's OSPF
cmd: |
  vtysh -c "configure terminal" \
        -c "router ospf" \
        -c "no redistribute eigrp" \
        -c "exit" -c "exit"

[POST-INJECT-CHECK]
r11  vtysh -c "show running-config" | grep "redistribute eigrp"  => expect empty
pc12 ping -W2 -c2 10.1.1.1                                          => expect loss>0

[GROUND-TRUTH]
Affected component: r11 OSPF process redistribution
Mechanism: r11 is the only bridge between the EIGRP cloud
  (r11/r12/r13 in AS 100) and the OSPF backbone (areas 0/1/2/3).
  Its `router ospf` block must `redistribute eigrp` to inject
  102.x, 112.x, 113.x, 120.x prefixes into OSPF; otherwise
  pc12's network 120.0.0.0/8 is invisible to R1 and the rest
  of the OSPF domain. Conversely, the EIGRP side learns the
  OSPF prefixes via r11's static default route (`ip route add
  default via 111.1.1.1`), so the EIGRP side may still see r11
  but not the broader topology if redistribution fails both ways.
Localization: r11
Root cause: r11's `router ospf` is missing `redistribute eigrp`
Fix: re-add `redistribute eigrp` to r11's OSPF block

[FIX]
re-add `redistribute eigrp` to r11's OSPF block

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm pc12 (120.1.1.x) cannot reach OSPF-backbone
   prefixes (10.x, 1.x, remote LANs) but R11 itself can reach the backbone;
   this points to a redistribution boundary failure, not a connectivity loss.
2. Check both routing tables: verify that 120.x/102.x/112.x/113.x prefixes
   are absent from R1's RIB (`show ip route` on r1) -- confirm the EIGRP
   prefixes are not being injected into OSPF.
3. Inspect the redistribution config at the boundary router: examine R11's
   OSPF process (`show running-config` on r11 | grep redistribute) to
   confirm `redistribute eigrp` is missing.
4. Explain the propagation gap: without `redistribute eigrp` in R11's OSPF
   block, the 102.x/112.x/113.x/120.x prefixes never become OSPF LSAs;
   the OSPF domain is blind to the EIGRP cloud.
5. Localize to the lowest-layer root cause: missing `redistribute eigrp`
   directive in R11's OSPF configuration; rule out a link failure or EIGRP
   adjacency problem (EIGRP neighbors are still up on R11).
