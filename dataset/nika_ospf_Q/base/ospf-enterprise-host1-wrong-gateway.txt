Helpdesk ticket #8876: host_1_1_1_1 (10.1.1.2) reports it cannot reach
anything outside its own subnet -- no server farm, no other pod, and name

[GROUND-TRUTH]
Affected component: host_1_1_1_1 default-gateway configuration
Mechanism: host_1_1_1_1's correct gateway is 10.1.1.1 (switch_dist_1_1's br0
  address). Its default route was repointed to 10.1.1.254 -- in-subnet but
  unassigned -- so ARP for the gateway never resolves and no off-subnet
  packet leaves the host. On-link destinations (10.1.1.1 via the connected
  route) still work, which is why the gateway pings fine. DNS "times out"
  only because the resolver 10.200.0.2 is off-subnet. The network itself is
  healthy: pod 2 reaches everything, and switch_dist_1_1 still advertises
  10.1.1.0/24.
Localization: host_1_1_1_1
Root cause: host_1_1_1_1's default gateway set to 10.1.1.254 instead of
  10.1.1.1
Fix: restore the default route on host_1_1_1_1 --
  `ip route replace default via 10.1.1.1 dev eth0`

[FIX]
restore host_1_1_1_1's default route --
`ip route replace default via 10.1.1.1 dev eth0`
