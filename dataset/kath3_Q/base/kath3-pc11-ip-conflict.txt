==================================================
Scenario: kath3-pc11-ip-conflict
Topology: Kath3
Fault family: IP address conflict
==================================================

[PROMPT-TO-AGENT]
PC11 and PC12 in Location C (192.168.200.x) both intermittently lose
connectivity. ARP for 192.168.200.12 flips between two MAC addresses on the
switch. Pings to PC12 sometimes succeed, sometimes fail. Diagnose.

[INJECTION]
device: pc11
action: reconfigure pc11 to PC12's IP (192.168.200.12 -- collision)
cmd: |
  ip addr flush dev eth0
  ip addr add 192.168.200.12/24 dev eth0
  ip route add default via 192.168.200.1 2>/dev/null

[POST-INJECT-CHECK]
pc11  ip -4 -br addr show eth0 | grep -c "192.168.200.12"  => expect 1

[GROUND-TRUTH]
Affected component: pc11 IP configuration -- duplicate of pc12
Mechanism: Both PC11 and PC12 advertise themselves as 192.168.200.12 via ARP.
  The switch FDB and the gateway's ARP cache flip between their MACs as they
  answer each other's gratuitous ARPs. Return traffic destined for .12 randomly
  reaches either host, causing flaky connectivity for both.
Localization: pc11 (and pc12 secondarily -- the collision is symmetric)
Root cause: pc11 was misconfigured with 192.168.200.12 (duplicate of pc12)
Fix: restore pc11 to its original IP (192.168.200.11)

[FIX]
restore pc11 to its original IP (192.168.200.11)

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm connectivity is intermittent/flapping rather than a
   hard failure -- pings to .12 give inconsistent results.
2. Look for ARP anomalies: inspect the switch FDB or ARP cache and observe that
   192.168.200.12 flips between two MAC addresses -- the signature of an IP
   conflict.
3. Identify both claimants: correlate the two MACs to the hardware addresses of
   PC11 and PC12.
4. Confirm the misconfigured host: check `ip addr show` on PC11 and find it was
   reconfigured to 192.168.200.12 instead of its original 192.168.200.11.
5. Localize to the root cause: PC11 has a duplicate IP (host-side misconfig);
   rule out a switch, VLAN, or routing fault since other Location C hosts behave
   normally.

[SCORING-AXES]
assert-identifies: pc11
must-identify-device: pc11 (the misconfigured host)
must-identify-component: duplicate IP / IP conflict
must-explain-arp-flapping
