==================================================
Scenario: kath3-router2-r1-link-down
Topology: Kath3
Fault family: WAN link cut
==================================================

[PROMPT-TO-AGENT]
Location B users (PC15-18, Laptop4/5) report they cannot reach
Location A or Location C any more. Internal Location B traffic
still works. Find what changed.

[INJECTION]
device: router2
action: shut down the link toward router1 (10.20.1.x)
cmd: ip link set eth2 down

[POST-INJECT-CHECK]
router2  ip -br link show eth2 | grep -c UP  => expect 0
router2  ping -W2 -c2 10.20.1.1              => expect loss>0
pc15     ping -W2 -c2 172.18.51.16           => expect 0% loss (intra-VLAN still works)

[GROUND-TRUTH]
Affected component: router2 eth2 / link router1<->router2
  (10.20.1.0/24)
Mechanism: router2 is the only WAN egress for the part of
  the topology serving Location B. With its link to router1
  down, RIP withdraws the path and Location B's prefixes
  (172.18.50/51.0/24) become unreachable from Locations A/C.
Localization: router2 eth2
Root cause: router1<->router2 link (10.20.1.0/24) is down
Fix: `ip link set eth2 up` on router2

[FIX]
`ip link set eth2 up` on router2

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm Location B hosts cannot reach Locations A and C, while
   intra-Location-B traffic (PC15 to PC16, etc.) still works -- the fault is at the
   WAN egress of Location B, not inside it.
2. Identify Location B's WAN egress: determine that router2 is the only WAN router
   for Location B and uplinks to router1 via 10.20.1.0/24.
3. Check the WAN link state on router2: inspect `ip -br link show eth2` on router2 --
   eth2 is down. Do NOT rely on Loc B -> Loc A pings as a test signal; router6's ACL
   blocks that path by design at baseline.
4. Confirm the RIP consequence: verify from router1 that Location B's prefixes
   (172.18.50/51.0/24) have been withdrawn, consistent with router2's link going down.
5. Localize to the lowest-layer root cause: the router1<->router2 physical link
   (10.20.1.0/24) is down; rule out router6 as the root cause (router6 is up and its
   ACL is pre-existing policy, not the fault).

[SCORING-AXES]
must-identify-affected-link: router1<->router2 / 10.20.1.0/24
# These axes score the outcome metric only; fix and reasoning are judged separately.

[DESIGN-NOTE]
Intentionally hard: the injection is two hops removed from Location B's
first-hop gateway (router6), and the most salient symptom (Loc B -> Loc A
unreachable) is ALREADY masked by router6's ACL 110 at baseline. Agents
that follow first-hop-bias diagnose router6 instead of router2; reaching
the correct diagnosis requires probing the WAN spine (router1<->router2)
past the gateway. This deliberately exercises first-hop-bias + ACL-masking
as a failure mode of LLM diagnostic agents: a clean example of how
enterprise security policy and LLM agent priors interact to mask fault
localization.
