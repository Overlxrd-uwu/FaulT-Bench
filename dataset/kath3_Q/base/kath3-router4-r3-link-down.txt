==================================================
Scenario: kath3-router4-r3-link-down
Topology: Kath3
Fault family: WAN link cut
==================================================

[PROMPT-TO-AGENT]
PC11-14 in Location C (192.168.200.x) report they cannot reach
Location A (172.16.10.x, 172.16.20.x) at all. Other zones can
still reach each other. Find what isolated Location C.

[INJECTION]
device: router4
action: shut down BOTH of router4's upstream links -- Location C is dual-homed (eth5 -> router3 over 172.25.1.x AND eth4 -> router5 over 192.168.15.x); both must drop to isolate it
cmd: |
  ip link set eth5 down
  ip link set eth4 down

[POST-INJECT-CHECK]
router4   ip -br link show eth5 | grep -c UP      => expect 0
router4   ip -br link show eth4 | grep -c UP      => expect 0
pc11      ping -W2 -c2 172.16.10.4                => expect loss>0

[GROUND-TRUTH]
Affected component: router4 uplinks eth5 (-> router3,
  172.25.1.0/24) AND eth4 (-> router5, 192.168.15.0/24)
Mechanism: router4 (Location C's edge) is DUAL-HOMED to the rest
  of the network -- via router3 over 172.25.1.0/24 (eth5) AND via
  router5 over 192.168.15.0/24 (eth4). Cutting only one uplink
  reroutes over the other with no outage, so BOTH must be down to
  isolate Location C. With both down, RIP withdraws every path and
  Location C loses Locations A and B.
Localization: router4 (both uplinks, eth5 and eth4)
Root cause: both of router4's upstream links are down
  (eth5 -> router3 and eth4 -> router5)
Fix: `ip link set eth5 up; ip link set eth4 up` on router4

[FIX]
`ip link set eth5 up; ip link set eth4 up` on router4

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm Location C hosts (PC11-14, 192.168.200.x) cannot reach
   Locations A or B, while Locations A and B can still reach each other -- the fault
   isolates Location C.
2. Identify Location C's WAN egress: determine that router4 is Location C's sole
   upstream router, connecting to the rest of the network via router3 over 172.25.1.0/24.
3. Check the link state on router4: inspect `ip -br link show eth5` on router4 --
   eth5 (toward router3) is down.
4. Confirm the RIP consequence: verify from router3 (or router1) that Location C's
   prefix (192.168.200.0/24) has been withdrawn from the RIP table, consistent with
   router4's link going down.
5. Localize to the lowest-layer root cause: the router4<->router3 physical link
   (172.25.1.0/24) is down; rule out a router3 or router1 failure since Locations
   A and B remain mutually reachable through those devices.

[SCORING-AXES]
must-identify-affected-link: router4's two uplinks (eth5 -> router3 and eth4 -> router5)
