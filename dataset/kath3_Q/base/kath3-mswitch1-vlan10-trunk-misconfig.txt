==================================================
Scenario: kath3-mswitch1-vlan10-trunk-misconfig
Topology: Kath3
Fault family: VLAN trunk subinterface down
==================================================

[PROMPT-TO-AGENT]
PC4 and PC5 (Location A VLAN 10, 172.16.10.0/24) report they
cannot reach their gateway (172.16.10.1) any more. Laptop0
on VLAN 20 in the same Location is unaffected. Find the
broken link in the L2 path.

[INJECTION]
device: mswitch1
action: bring down the VLAN 10 trunk subinterface on the
  uplink toward router0
cmd: ip link set eth0.10 down

[POST-INJECT-CHECK]
mswitch1  ip -br link show eth0.10 | grep -c UP  => expect 0
pc4       ping -W2 -c2 172.16.10.1               => expect loss>0
laptop0   ping -W2 -c2 172.16.20.1               => expect 0% loss

[GROUND-TRUTH]
Affected component: mswitch1 eth0.10 (VLAN 10 trunk subif
  toward router0)
Mechanism: mswitch1 has separate per-VLAN trunk subinterfaces
  for VLAN 10 and VLAN 20. PC4/PC5's gateway (router0
  eth0.10 at 172.16.10.1) sits on the far side of this
  trunk. With eth0.10 down on mswitch1, no VLAN 10 frames
  reach router0 — ARP and ping both fail. VLAN 20 uses
  eth0.20 which is unaffected.
Localization: mswitch1
Root cause: eth0.10 trunk subinterface administratively down
Fix: `ip link set eth0.10 up` on mswitch1

[FIX]
`ip link set eth0.10 up` on mswitch1

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm only PC4/PC5 (VLAN 10) are affected; Laptop0 (VLAN 20)
   still reaches its gateway -- the fault is VLAN-scoped, not a full switch outage.
2. Check host L3 config: verify PC4/PC5 have correct IPs, subnet masks, and default
   gateway (172.16.10.1) -- confirm the issue is not a host misconfiguration.
3. Check switch port VLAN membership: inspect mswitch1 port assignments to confirm
   PC4/PC5 ports are in VLAN 10 -- rule out an access-port misconfiguration.
4. Check the trunk toward router0: inspect the per-VLAN subinterfaces on mswitch1's
   uplink -- eth0.10 (VLAN 10) is down while eth0.20 (VLAN 20) is up.
5. Check SVI/gateway reachability: confirm router0's eth0.10 subinterface (172.16.10.1)
   is intact and that the fault is on the mswitch1 side, not the router side.
6. Localize to the lowest-layer root cause: mswitch1 eth0.10 trunk subinterface is
   administratively down; rule out a VLAN membership error or router-side subif failure.
