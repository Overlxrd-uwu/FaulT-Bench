==================================================
Scenario: kath3-laptop0-wrong-gateway
Topology: Kath3
Fault family: host misconfig (wrong default gateway)
==================================================

[PROMPT-TO-AGENT]
Laptop0 (172.16.20.10, Location A VLAN 20) reports it cannot reach anything
outside its own VLAN -- not Location C, not the rest of the network -- though it
still reaches other VLAN 20 hosts. PC4/PC5 on VLAN 10 are unaffected. Diagnose
Laptop0.

[INJECTION]
device: laptop0
action: point Laptop0's default route at a non-existent in-subnet gateway
cmd: |
  ip route del default 2>/dev/null
  ip route add default via 172.16.20.99

[POST-INJECT-CHECK]
laptop0  ip route show default | grep -c "172.16.20.99"   => expect 1
laptop0  ping -W2 -c2 192.168.100.1                        => expect loss>0

[GROUND-TRUTH]
Affected component: laptop0 default-gateway configuration
Mechanism: Laptop0's correct gateway is 172.16.20.1 (router0's VLAN 20
  sub-interface). It was reconfigured to 172.16.20.99 -- in-subnet but
  unassigned -- so ARP for the gateway never resolves and Laptop0 cannot forward
  off-subnet traffic. VLAN 20 peers remain reachable (direct ARP); the rest of
  Location A and the network are healthy.
Localization: laptop0
Root cause: Laptop0's default gateway set to 172.16.20.99 instead of 172.16.20.1
Fix: restore Laptop0's default route -- `ip route add default via 172.16.20.1`

[FIX]
restore Laptop0's default route -- `ip route add default via 172.16.20.1`

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm Laptop0 cannot reach off-VLAN destinations while
   VLAN 20 peers are reachable and VLAN 10 hosts are unaffected -- isolate to
   Laptop0's own L3 config.
2. Inspect Laptop0's routing: `ip route show default` -- the default points at
   172.16.20.99 rather than the expected 172.16.20.1.
3. Confirm the ARP consequence: 172.16.20.99 is in-subnet but unassigned, so the
   gateway never resolves and no off-subnet packet egresses.
4. Localize to Laptop0's host config: rule out a router0 sub-interface fault (the
   real gateway 172.16.20.1 is up) and a link/RIP failure (VLAN 20 peers and the
   rest of Location A are fine).
