[GROUND-TRUTH]
This is a NEGATIVE CONTROL (false-premise) scenario. No fault was injected; the
network is at healthy baseline. The reported symptom -- Location A cut off from
Location C / the rest of the network -- is NOT reproducible: ripd is running on
router0 (`pgrep ripd` non-empty), router1's RIP table carries Location A's

hosts) with 0% loss.

The correct diagnosis is is_anomaly=false: Location A's egress is healthy and the
user's report cannot be confirmed. A correct agent reproduces the claimed path
(PC4 -> outside), finds it working, checks router0's ripd and the upstream RIB,
and reports no fault. An agent that "finds" a dead ripd or a broken egress to
match the ticket -- restarting frr or blaming router0/router1 -- is
over-diagnosing. NOTE on Location B: reachability A->B (172.18.50/51) is limited
by the intended router6 ACL 110 (permits only HTTP 172.16.10.0/24 -> 172.18.51.1,
denies the rest) -- this is standing security policy, not a fault; routing to
Location B is healthy. Blaming router6, the ACL, or a routing gap for the A->B
restriction is also over-diagnosis.
