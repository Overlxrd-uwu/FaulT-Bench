==================================================
Scenario: kath2-router1-r0-link-down
Topology: Kath2
Fault family: link cut
==================================================

[PROMPT-TO-AGENT]
The TPO terminal (192.168.3.5) reports they cannot reach any
Internet Lab PC (128.168.0.x). At the same time, every PC in
the IT Department and CS Department reports they cannot reach
ANYTHING outside their own department. The Principle Room and
Other zone can still reach the Server Room and Internet Lab
normally. Find what broke.

[INJECTION]
device: router1
action: bring down the WAN-side link to router0
cmd: ip link set eth2 down

[POST-INJECT-CHECK]
router1  ip -br link show eth2 | grep -c UP  => expect 0
tpo      ping -W2 -c2 128.168.0.2            => expect 0% loss   (still OK)
it_hod   ping -W2 -c2 192.168.3.2            => expect loss>0   (broken)

[GROUND-TRUTH]
Affected component: router1's Serial2/0 (eth2) interface, the
  10.10.0.0/8 link between router0 and router1
Mechanism: router0 is the gateway for IT (192.168.1.0/24)
  and CS (192.168.2.0/24). It only reaches the rest of the
  network (router1, router2, all their attached subnets) via
  the Serial link to router1. With that link down, RIP on
  router1 ages out 192.168.1.0/24 and 192.168.2.0/24, and
  router0 ages out everything else. The TPO->128.168.0.2
  path is router1 -> router2 -> Switch5, which does NOT
  cross the down link, so it stays up.
Localization: router1 eth2 (or router0 eth2 — both ends of
  the 10.10.0.0/8 link)
Root cause: WAN link router0<->router1 (10.10.0.0/8) is down
Fix: `ip link set eth2 up` on router1 (or router0 if that side
  is down)

[FIX]
`ip link set eth2 up` on router1 (or router0 if that side
  is down)

[DIAGNOSTIC-PROCESS]
1. Scope the symptom pattern: IT Dept and CS Dept lose all connectivity; TPO
   and Other/Principle zones still reach Server Room and Internet Lab. IT/CS
   share router0 as their only gateway, so the fault must be at or beyond
   router0's upstream path.
2. Layer 1/2 first: check interface state on router1 and router0 — router1
   eth2 (the WAN/serial link toward router0) is down.
3. Confirm link identity: the downed interface carries the 10.10.0.0/8 serial
   segment between router0 and router1 — the only path for IT/CS traffic to
   leave router0's broadcast domain.
4. Correlate with the routing plane: with the link down, RIP on router1 ages
   out 192.168.1.0/24 and 192.168.2.0/24; router0 ages out all remote prefixes.
   TPO->Internet Lab path (router1->router2->Switch5) does not cross this link
   and stays up.
5. Localize to the router0<->router1 link (10.10.0.0/8): rule out a ripd crash
   by checking that both daemons are running; the link state is the lowest-layer
   cause.

[SCORING-AXES]
must-identify-affected-link: router0-router1 10.10.0.0/8
must-distinguish-symptom-pattern: only IT/CS are affected, not Other/Principle
