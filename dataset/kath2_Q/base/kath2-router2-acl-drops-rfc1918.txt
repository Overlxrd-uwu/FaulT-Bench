==================================================
Scenario: kath2-router2-acl-drops-rfc1918
Topology: Kath2
Fault family: ACL drops legitimate transit
==================================================

[PROMPT-TO-AGENT]
IT and CS Dept users report they cannot reach Server Room
(1.0.0.x) and Internet Lab (128.168.0.x). But Other zone
(192.168.3.x) and Principle Room (192.168.4.x) CAN reach
those targets. router2 shows RIP routes intact and ip_forward
on. Identify what blocks IT/CS but not Other/Principle.

[INJECTION]
device: router2
action: add FORWARD DROP rules for IT (192.168.1.0/24) and CS (192.168.2.0/24)
cmd: |
  iptables -A FORWARD -s 192.168.1.0/24 -j DROP
  iptables -A FORWARD -s 192.168.2.0/24 -j DROP

[POST-INJECT-CHECK]
it_hod   ping -W2 -c2 1.0.0.5                            => expect loss>0
office_pc ping -W2 -c2 1.0.0.5                           => expect 0% loss

[GROUND-TRUTH]
Affected component: router2 iptables FORWARD chain
Mechanism: New DROP rules block any forwarded packet whose
  source is in 192.168.1.0/24 (IT Dept) or 192.168.2.0/24
  (CS Dept). Office (192.168.3.x) and Principle (192.168.4.x)
  source addresses are not matched, so they are unaffected.
  Routing is healthy; the drop is at the firewall layer.
Localization: router2
Root cause: extraneous iptables FORWARD DROP rules for
  192.168.1.0/24 (IT) and 192.168.2.0/24 (CS)
Fix: `iptables -D FORWARD -s 192.168.1.0/24 -j DROP && iptables -D FORWARD -s 192.168.2.0/24 -j DROP` on router2

[FIX]
remove both DROP rules on router2 — `iptables -D FORWARD -s 192.168.1.0/24 -j DROP && iptables -D FORWARD -s 192.168.2.0/24 -j DROP`

[DIAGNOSTIC-PROCESS]
1. Scope the selective failure: confirm IT (192.168.1.0/24) and CS
   (192.168.2.0/24) hosts cannot reach 1.0.0.x and 128.168.0.x, while Office
   (192.168.3.x) and Principle (192.168.4.x) hosts reach those targets
   normally. The source-dependent pattern points to a filter, not a routing
   problem.
2. Verify routing is healthy: check RIP tables and ip_forward on router2 — both
   intact — confirming the issue is above the routing layer.
3. Inspect the ACL on the transit device: run `iptables -nL FORWARD` (or
   `nft list ruleset` — same rules under the iptables-nft backend) on router2 —
   two DROP rules are present, one for source 192.168.1.0/24 (IT) and one for
   192.168.2.0/24 (CS).
4. Confirm the source-filter mechanism: Office (192.168.3.x) and Principle
   (192.168.4.x) match neither rule; IT and CS sources are dropped in the
   FORWARD chain before the packet can be delivered.
5. Localize to the iptables FORWARD rules on router2: rule out a link failure or
   ripd crash as the cause, since routing is healthy for all sources and only
   forwarded traffic from the two /24 ranges is dropped.
