==================================================
Scenario: kath2-router2-r1-link-down
Topology: Kath2
Fault family: WAN link cut
==================================================

[PROMPT-TO-AGENT]
Office and Principle Room users (192.168.3.x, 192.168.4.x)
report they cannot reach Server Room (1.0.0.x) or Internet Lab
(128.168.0.x). IT Department and CS Department users say the
same. But Server Room ↔ Internet Lab works fine internally.
Find the broken link.

[INJECTION]
device: router2
action: shut down the WAN link to router1
cmd: ip link set eth2 down

[POST-INJECT-CHECK]
router2  ip -br link show eth2 | grep -c UP  => expect 0
office_pc ping -W2 -c2 1.0.0.5               => expect loss>0
pc1      ping -W2 -c2 128.168.0.2            => expect 0% loss (internal)

[GROUND-TRUTH]
Affected component: router2 Serial2/0 (eth2), 20.20.0.0/8 link
Mechanism: router1 ↔ router2 over the 20.20.0.0/8 serial is
  the only path connecting routers 0/1's subnets to router2's
  Server Room + Internet Lab. With the link down, RIP on both
  sides ages out the unreachable prefixes and connectivity
  splits into two islands (router0+router1 side / router2 side).
Localization: router2 eth2 (or router1 eth3)
Root cause: WAN link router1<->router2 (20.20.0.0/8) is down
Fix: `ip link set eth2 up` on router2

[FIX]
`ip link set eth2 up` on router2

[DIAGNOSTIC-PROCESS]
1. Scope the symptom split: all zones (IT, CS, Office, Principle) lose access to
   Server Room and Internet Lab, while Server Room <-> Internet Lab traffic
   remains healthy internally. This total island split suggests the single link
   connecting router2's side to the rest of the network is down.
2. Layer 1/2 first: check interface state on router2 and router1 — router2
   eth2 (the WAN/serial link toward router1) is down.
3. Confirm link identity: the downed interface carries the 20.20.0.0/8 serial
   segment between router1 and router2 — the only inter-router path bridging
   the two islands.
4. Correlate with the routing plane: with the link down, RIP on both sides ages
   out the opposite prefixes. The router0+router1 side loses 1.0.0.0/8 and
   128.168.0.0/16; router2 loses all 192.168.x.x prefixes. Server Room <->
   Internet Lab stays up because that path is entirely within router2's side.
5. Localize to the router1<->router2 link (20.20.0.0/8): rule out ripd crashes
   by confirming daemons are running on both routers; the link state is the
   lowest-layer cause.
