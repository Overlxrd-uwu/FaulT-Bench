==================================================
Scenario: kath2-rip-version-mismatch
Topology: Kath2
Fault family: RIP version mismatch
==================================================

[PROMPT-TO-AGENT]
After a config change on router2, RIP routes for 1.0.0.0/8 and
128.168.0.0/16 disappeared from router1's routing table. router2
still sees its own connected networks. router1 still has all
other RIP routes. router2 reports it's sending updates but
nobody receives them. Investigate.

[INJECTION]
device: router2
action: switch RIP to version 1 (so v2 peers won't accept the
  classful updates, or vice versa depending on stack)
cmd: |
  vtysh -c "configure terminal" \
        -c "router rip" \
        -c "version 1" \
        -c "exit" -c "exit"

[POST-INJECT-CHECK]
router2  vtysh -c "show running-config" | grep -c " version 1"   => expect 1

[GROUND-TRUTH]
Affected component: router2 RIP version
Mechanism: router0 and router1 run RIPv2; router2 was switched
  to RIPv1. The two versions use different packet formats and
  v2 peers drop v1 updates by default (and vice versa). router2
  is "sending" updates that router1 ignores. router2's own
  connected networks stay in its RIB; only advertised ones
  vanish elsewhere.
Localization: router2
Root cause: RIP version mismatch (router2 v1, neighbors v2)
Fix: `vtysh -c "router rip" -c "version 2"` on router2

[FIX]
`vtysh -c "router rip" -c "version 2"` on router2

[DIAGNOSTIC-PROCESS]
1. Scope the missing routes: confirm on router1 that RIP routes for 1.0.0.0/8
   and 128.168.0.0/16 are absent while other RIP routes remain, narrowing the
   problem to prefixes sourced from router2.
2. Check RIP adjacency / updates: on router1 check whether RIP updates arrive
   from router2's address; observe that updates are sent but not accepted.
3. Compare RIP version config: run `vtysh -c "show running-config"` on both
   router1 and router2 — router2 shows `version 1`, router1 (and router0) run
   v2. v1 and v2 use incompatible packet formats; v2 peers drop v1 updates by
   default.
4. Localize to the version mismatch on router2: router2's connected networks
   stay in its own RIB (not dependent on receiving updates), but its
   advertisements are silently discarded by its v2 neighbors. Rule out a link
   failure or daemon crash as the cause.
