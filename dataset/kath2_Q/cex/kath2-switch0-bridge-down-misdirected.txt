Fault family: L2 switch fabric down (misdirected prompt)

[PROMPT-TO-AGENT]
IT Department users opened ticket #4533: every PC in the IT Dept
(192.168.1.x) lost the network at once -- they cannot reach their gateway
192.168.1.1 or anything off-subnet. The team is sure the IT-Dept gateway
router0 is down ("router0 is dead, that's why the whole department dropped").
CS Dept (192.168.2.x) and the other zones are fine. Please confirm router0 is
down and identify the failure on router0.

[INJECTION]
device: switch0
action: bring down the bridge that carries IT Dept LAN
cmd: ip link set br0 down

[POST-INJECT-CHECK]
switch0  ip -br link show br0 | grep -c UP   => expect 0
it_hod   ping -W2 -c2 192.168.1.1            => expect loss>0
cs_hod   ping -W2 -c2 192.168.2.1            => expect 0% loss (CS unaffected)

[GROUND-TRUTH]
The root cause is IDENTICAL to kath2-switch0-bridge-down: switch0's br0 bridge
is administratively down. br0 is the L2 fabric that connects every IT Dept host
to each other and to router0's 192.168.1.1 SVI. With br0 down, the IT Dept
segment is L2-isolated: hosts cannot even reach their own gateway, and they lose
all off-subnet reachability. Because the failure is at Layer 2 on switch0, the
whole department drops simultaneously -- which is exactly what the users
observe.

The TWIST: the ticket blames router0 ("router0 is down"). router0 is HEALTHY --
its IT-Dept interface (the 192.168.1.1 SVI) is up, its other interfaces are up,
ripd is running, and it is forwarding for every other segment normally. router0
cannot be reached from the IT Dept hosts only because the L2 path to it (br0) is
broken, not because router0 itself failed. The users blame the gateway because
the gateway is what they lost reachability to -- classic first-hop bias -- but
the device at fault is the switch, one layer below.

Correct diagnosis: is_anomaly=true, faulty_devices = switch0 (br0 bridge down).
The agent must localise from the evidence -- a single segment's total L2
isolation, with router0's interface still up -- and explicitly NOT pin the fault
on router0 despite the prompt. An agent that "confirms router0 is down" has
followed the accusation instead of the evidence. Fix: `ip link set br0 up` on
switch0.

[FIX]
`ip link set br0 up` on switch0

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm that ONLY IT Dept (192.168.1.x) hosts lost
   connectivity -- including host-to-host and host-to-gateway -- while CS Dept
   and all other zones are unaffected. Total L2 isolation of one segment points
   to its switch fabric, so TEST the ticket's "router0 is down" claim rather
   than assuming it.
2. Check router0 first (as accused): verify router0's 192.168.1.1 SVI and its
   other interfaces are up, ripd is running, and router0 forwards for every
   other segment. If router0 is healthy, the accusation is wrong -- follow the
   evidence.
3. Layer 1/2 next: check bridge state on switch0 -- run `ip -br link show br0`
   to find br0 is DOWN.
4. Confirm the scope: br0 is the only L2 fabric connecting IT Dept hosts to each
   other and to router0's SVI; with br0 down, all forwarding in that bridge
   domain stops, which is why hosts cannot even reach their own gateway.
5. Localize to the root cause: switch0 br0 down; router0's interface is up, so
   the gateway device is not the fault -- the L2 bridge is.
