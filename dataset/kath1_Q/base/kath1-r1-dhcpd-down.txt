==================================================
Scenario: kath1-r1-dhcpd-down
Topology: Kath1
Fault family: service down (DHCP server)
==================================================

[PROMPT-TO-AGENT]
A user reboots their PC and now cannot get an IP address. Other
PCs that were already up keep working (their existing leases are
still valid). Newly connected devices on any internal VLAN time
out waiting for DHCP. Existing TCP sessions are unaffected.
Diagnose.

[INJECTION]
device: r1
action: stop dhcpd
cmd: pkill -9 dhcpd

[POST-INJECT-CHECK]
r1  pgrep dhcpd                                          => expect empty

[GROUND-TRUTH]
Affected component: r1 dhcpd (ISC DHCP server)
Mechanism: r1 is the central DHCP server for every internal
  VLAN (A-PC, A-Phone, A-Mgmt, B-PC, B-Phone, B-Mgmt, Wi-Fi).
  DSWs relay DHCPDISCOVER as unicast to 10.0.0.76 (R1's
  loopback). With dhcpd dead, requests reach r1 but get no
  reply. Existing leases keep working until their lifetime
  expires; renewals start failing after lease-time/2.
Localization: r1
Root cause: dhcpd is not running on r1
Fix: restart dhcpd — `/etc/init.d/isc-dhcp-server restart`
  on r1 (or however the lab launches dhcpd)

[FIX]
restart dhcpd — `/etc/init.d/isc-dhcp-server restart`
  on r1 (or however the lab launches dhcpd)

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: only newly connecting or rebooting devices fail to get
   an IP; devices that were already up keep working -- this points to a DHCP
   lease acquisition failure, not a routing or link fault.
2. Check the DHCP server process on r1: `pgrep dhcpd` returns empty --
   dhcpd is not running on r1.
3. Check relay reachability: DSWs relay DHCPDISCOVER unicast to r1's
   loopback 10.0.0.76; if r1 is reachable but dhcpd is dead, requests
   arrive and are silently dropped.
4. Confirm the existing-vs-new distinction: current lease holders keep their
   addresses until lease expiry; renewals (at lease-time/2) will start
   failing -- the fault worsens over time if dhcpd stays down.
5. Localize to the root cause: dhcpd process not running on r1; rule out a
   relay misconfiguration (relay targets 10.0.0.76 which is still routable)
   and a link failure (existing leases and all other traffic are intact).
