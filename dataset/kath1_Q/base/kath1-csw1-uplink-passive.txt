==================================================
Scenario: kath1-csw1-uplink-passive
Topology: Kath1
Fault family: OSPF passive-interface misconfig
==================================================

[PROMPT-TO-AGENT]
After a routine config change on CSW1, R1 lost an OSPF neighbor.
Internet traffic still works but uses only the CSW2 path. CSW1's
eth0 link to R1 is physically UP, IP addresses match, ping
between CSW1's eth0 (10.0.0.34) and R1's eth0 (10.0.0.33) works.
Why is no OSPF adjacency forming?

[INJECTION]
device: csw1
action: mark the R1-facing interface as OSPF passive
cmd: |
  vtysh -c "configure terminal" \
        -c "router ospf" \
        -c "passive-interface eth0" \
        -c "exit" -c "exit"

[POST-INJECT-CHECK]
csw1  vtysh -c "show ip ospf interface eth0" | grep -i passive   => expect non-empty
csw1  vtysh -c "show ip ospf neighbor" | grep 10.0.0.76          => expect empty

[GROUND-TRUTH]
Affected component: csw1 OSPF passive-interface config on eth0
Mechanism: `passive-interface` tells OSPF to advertise the
  subnet but NOT to send hellos on it. The L2/L3 link is fine,
  but no OSPF adjacency forms because both ends never exchange
  hellos. r1 doesn't learn about networks reachable via csw1's
  eth0, and csw1 doesn't learn r1's loopback over this path.
Localization: csw1
Root cause: `passive-interface eth0` set on csw1's OSPF
  process when it should be active (eth0 faces a peer router)
Fix: `vtysh -c "router ospf" -c "no passive-interface eth0"`
  on csw1

[FIX]
`vtysh -c "router ospf" -c "no passive-interface eth0"`
  on csw1

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm CSW1 has no OSPF adjacency to R1 while the
   link (eth0) is physically UP and ping between 10.0.0.34 and 10.0.0.33
   succeeds -- L2/L3 connectivity is intact.
2. Check the OSPF neighbor table: `show ip ospf neighbor` on csw1 shows
   R1 (10.0.0.76 / 10.0.0.33) is absent despite the working link.
3. Inspect the interface OSPF state: `show ip ospf interface eth0` -- look
   for "Passive" status, which would explain why hellos are suppressed.
4. Confirm the mechanism: passive-interface causes OSPF to advertise the
   subnet but never send hellos, so neither side forms an adjacency -- not
   a link failure, not an IP mismatch, not an area mismatch.
5. Localize to the root cause: `passive-interface eth0` is set in csw1's
   OSPF process when eth0 faces a peer router and must be active; rule out
   link-down or IP misconfiguration (ping works, IPs match).
