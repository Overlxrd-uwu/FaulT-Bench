==================================================
Scenario: kath1-r1-default-route-removed
Topology: Kath1
Fault family: default route missing
==================================================

[PROMPT-TO-AGENT]
Internal traffic between Office A and Office B works fine.
DSWs/CSWs report all OSPF neighbors Full. But Internet-bound
traffic (e.g., reaching 203.0.113.1) from any internal PC
times out. R1 itself can reach internal devices but cannot
reach the ISP gateways. Diagnose.

[INJECTION]
device: r1
action: delete the default route
cmd: ip route del default

[POST-INJECT-CHECK]
r1   ip route show default                  => expect empty
pc1  curl -s -m 5 -o /dev/null -w "%{http_code}" http://203.0.113.1  => expect 0

[GROUND-TRUTH]
Affected component: r1 default route
Mechanism: r1 is the only egress to the ISPs. Without a
  default route, packets destined to public IPs (anything
  not in 10.0.0.0/8 or 203.0.113.0/30) have no next hop on
  r1 and are dropped. Internal traffic stays inside the
  OSPF domain so it's unaffected. The fact that r1's
  OSPF neighbors are still Full distinguishes this from
  an OSPF daemon failure.
Localization: r1
Root cause: default route missing from r1's routing table
Fix: re-add default — `ip route add default via 203.0.113.1`
  (or restart frr if it was sourced via OSPF default-information
  originate from an ISP)

[FIX]
re-add default — `ip route add default via 203.0.113.1`
  (or restart frr if it was sourced via OSPF default-information
  originate from an ISP)

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: all internal traffic is fine and OSPF neighbors are
   Full everywhere -- the fault is exclusively on the Internet-egress path,
   not the OSPF domain.
2. Check R1's routing table: `ip route show` on r1 -- no default route
   (0.0.0.0/0) is present, but all internal (10.0.0.0/8) routes are intact.
3. Trace the failure path: R1 is the sole egress to the ISPs; without a
   default route, any packet destined to a public IP has no next hop on r1
   and is dropped silently.
4. Confirm OSPF is healthy: `show ip ospf neighbor` on r1 shows Full
   adjacencies with CSW1/CSW2 -- the missing default is not caused by
   ospfd being down or a neighbor loss.
5. Localize to the root cause: default route missing from r1's routing
   table; rule out an OSPF daemon failure (neighbors are Full) and a NAT
   failure (internal-to-internal works, and pings from r1 itself also fail
   externally).
