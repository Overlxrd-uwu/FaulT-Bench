==================================================
Scenario: kath1-r1-ospfd-down
Topology: Kath1
Fault family: routing daemon down
==================================================

[PROMPT-TO-AGENT]
Users on PC1 (10.1.0.100) in Office A report they cannot reach
anything outside their own VLAN. Internal pings to other Office-A
data PCs still work, but Internet access and reaching Office B
services hang. Investigate.

[INJECTION]
device: r1
action: kill ospfd
cmd: pkill -9 watchfrr; pkill -9 ospfd

[POST-INJECT-CHECK]
r1            pgrep ospfd                       => expect empty
pc1           ping -W2 -c2 10.0.0.76            => expect loss>0

[GROUND-TRUTH]
Affected component: r1 ospfd daemon
Mechanism: r1 stopped sending OSPF hellos and LSAs. CSW1/CSW2
  aged out r1's loopback (10.0.0.76) and the default route r1
  originated via `default-information originate`. Office-A
  internal traffic still works because DSWs route locally,
  but anything beyond the OSPF backbone (Internet, Office B
  via core) has no next hop and is dropped.
Localization: r1
Root cause: OSPF routing daemon (ospfd) not running on r1
Fix: restart frr on r1 — `/etc/init.d/frr restart`

Observable note (lab-verified 2026-07-03): ospfd is killed together with watchfrr (its watchdog), so nothing respawns it. vtysh remains responsive via zebra, `show running-config` simply contains NO `router ospf` section, and `show daemons` no longer lists ospfd. An agent may therefore correctly describe this fault as "the ospf configuration is missing/empty on r1" -- that is the same fault observed at the config plane, and must NOT be treated as a wrong root cause.

[FIX]
restart frr on r1 — `/etc/init.d/frr restart`

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: Office-A intra-VLAN traffic works but cross-VLAN,
   Office-B, and Internet traffic all fail -- the fault is at the OSPF
   backbone layer (r1 is the hub), not a local switch or VLAN issue.
2. Inspect the OSPF neighbor table on CSW1/CSW2: `show ip ospf neighbor`
   -- r1's router-ID is absent or in Down/Exstart; other adjacencies
   (DSWs) are still Full.
3. Check the routing daemon on r1: `pgrep ospfd` returns empty -- ospfd
   is not running, so r1 has stopped sending hellos and LSAs.
4. Trace the mechanism: without ospfd, CSW1/CSW2 age out r1's loopback
   (10.0.0.76) and the default route r1 originated via
   `default-information originate`; routes to Office B and Internet via r1
   disappear from every device in the OSPF domain.
5. Localize to the root cause: ospfd process not running on r1; rule out a
   link failure (Office-A local traffic works, confirming DSW-to-CSW links
   are intact) and an ACL or NAT issue (the fault is pre-routing, not at
   the egress boundary).
