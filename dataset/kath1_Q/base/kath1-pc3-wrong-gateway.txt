==================================================
Scenario: kath1-pc3-wrong-gateway
Topology: Kath1
Fault family: host misconfig (wrong default gateway)
==================================================

[PROMPT-TO-AGENT]
PC3 (10.3.0.100) in Office B reports it cannot reach anything outside its own
subnet -- no Internet, no Office A, no Server Room -- though it can still reach
other hosts on its own VLAN. Other Office B hosts are unaffected. PC3 was working
before a desktop reconfiguration. Diagnose.

[INJECTION]
device: pc3
action: point PC3's default route at a non-existent in-subnet gateway
cmd: |
  ip route del default 2>/dev/null
  ip route add default via 10.3.0.99

[POST-INJECT-CHECK]
pc3  ip route show default | grep -c "10.3.0.99"   => expect 1
pc3  ping -W2 -c2 10.1.0.100                        => expect loss>0

[GROUND-TRUTH]
Affected component: pc3 default-gateway configuration
Mechanism: PC3's correct gateway is 10.3.0.1 (its VLAN SVI/VRRP VIP). It was
  reconfigured to 10.3.0.99, which is inside PC3's subnet but is not assigned to
  any device, so ARP for the gateway never resolves and PC3 cannot forward any
  off-subnet traffic. Same-subnet hosts remain reachable (direct ARP), which is
  why intra-VLAN traffic still works.
Localization: pc3
Root cause: PC3's default gateway set to 10.3.0.99 instead of 10.3.0.1
Fix: restore PC3's default route -- `ip route add default via 10.3.0.1`

[FIX]
restore PC3's default route -- `ip route add default via 10.3.0.1`

[DIAGNOSTIC-PROCESS]
1. Scope the symptom: confirm PC3 cannot reach any off-subnet destination while
   same-VLAN peers are reachable, and other Office B hosts are unaffected -- this
   isolates the fault to PC3's own L3 config.
2. Inspect PC3's routing: `ip route show default` -- the default points at
   10.3.0.99, not the expected 10.3.0.1.
3. Confirm the ARP consequence: 10.3.0.99 is in-subnet but unassigned, so ARP for
   the gateway fails and no off-subnet packet can egress.
4. Localize to PC3's host config: rule out a gateway/router fault (the real
   gateway 10.3.0.1 is up and serves other Office B hosts) and a link failure
   (intra-VLAN traffic works).
