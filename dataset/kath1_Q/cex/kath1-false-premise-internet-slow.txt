the network is at healthy baseline. The reported symptom -- Office A Internet
is slow and intermittent -- is NOT reproducible: PC1 (10.1.0.100) reaches the
ISP edge 203.0.113.1 with 0% loss, R1 MASQUERADEs 10.1.0.0/24 out its ISP

The correct diagnosis is is_anomaly=false: the egress path is healthy and the
user's report cannot be confirmed by direct evidence. A correct agent probes

loss, check R1's NAT and default route), finds it healthy and stable, and
reports no fault. An agent that "finds" a fault here -- blaming the ISP, an R1

over-diagnosing: confirming the premise instead of testing it. A subjective
performance complaint with no reproducible loss is not a network fault.

Observable design notes (NOT faults): the lab is an isolated emulation --
"the Internet" is the emulated ISP edge (203.0.113.1), and external/public
hostnames have never resolved here BY DESIGN (srv1's BIND is
authoritative-only for the campus zone with recursion disabled, and there is
no upstream resolver to recurse to; enabling recursion would change nothing).
Latency/loss claims are therefore scoped to the emulated egress path, which
is lossless. An agent citing srv1's recursion-off config or external-name
non-resolution as the cause of "slow/intermittent Internet" has invented a
fault the egress path does not exhibit.
